# Accent colour — design

Date: 2026-10-01 · Status: approved in chat, awaiting review of this document

## Goal

Let anyone using Kanto change its primary colour — violet to blue, green or
any colour — easily, with contrast guaranteed, and let a visitor of the docs
site try it from a colour chooser in the top bar, left of the theme switch.

Decided with Arnaud:

- **Scope:** a real theming API in the library, used by the docs site's
  chooser. No public picker component.
- **Choice:** a palette of tuned presets plus any colour.
- **Surfaces:** the neutral ramp, today tinted violet, follows the accent.

## What exists

- The accent is four tokens in `src/tokens/colors.css`:
  `--color-primary-base` (`oklch(0.562 0.207 278)`), `-hover`, `-soft`
  (12% alpha) and `-text`, redefined in `theme-light.css` (twice: for
  `data-theme="light"` and for `data-theme="auto"` under
  `prefers-color-scheme: light`). `--color-secondary-hover` is a 16% violet
  wash used by secondary buttons and toggle buttons.
- Components use only these tokens (≈100 uses); no primary value is
  hard-coded in a component.
- The neutral ramp (`--color-dark-8…24`, `--color-text-100…900`) has OKLCH
  chroma 0.003–0.02 at hue 286–297: a grey tinted by the accent.
- `--color-white` is the text on primary fills; `-base` is tuned to carry it
  at 4.5:1.

## Design

### 1. Token layering: inputs, then tokens

The public token names do not change. They stop holding colours and read a
few **accent inputs** instead, each with today's value as its fallback:

| Input                 | Meaning                                       | Default (violet)       |
| --------------------- | --------------------------------------------- | ---------------------- |
| `--accent-base`       | Solid fill, carries white text at ≥ 4.5:1     | `rgba(95, 93, 234, 1)` |
| `--accent-hover`      | Fill on hover, one step darker                | `rgba(88, 86, 224, 1)` |
| `--accent-text-dark`  | Accent as text/icon in the dark theme         | `#8e97ff`              |
| `--accent-text-light` | Accent as text/icon in the light theme        | `#4f30ef`              |
| `--neutral-hue`       | Hue the neutral ramp is tinted with (degrees) | today's, see below     |

- `--color-primary-base: var(--accent-base, …)`; `-hover` likewise;
  `-soft` and `--color-secondary-hover` become
  `color-mix(in srgb, var(--color-primary-base) 12% | 16%, transparent)`.
- `--color-primary-text` reads `--accent-text-dark` in `colors.css` and
  `--accent-text-light` in both light blocks of `theme-light.css` — so the
  theme switch keeps working with no script.
- Each neutral step becomes `oklch(L C var(--neutral-hue))` with its current
  L and C. The ramp today drifts between 286° and 297°; it is rewritten with
  per-step hues expressed as `calc(var(--neutral-hue) + offset)` so that the
  default renders the same values to within one sRGB unit. A snapshot test
  holds this.
- A colour with no chroma (grey) as accent gives grey neutrals: the neutral
  chroma is scaled by `--neutral-chroma` (default 1), which `accentPalette`
  sets to 0 for an achromatic colour.

Inputs set on `<html>` theme the page; set on any element they theme that
subtree, as `data-theme` already does.

### 2. Presets — `src/tokens/accents.css`

Imported by `tokens/index.css` (so by `styles.css`). Seven presets, each a
block setting the inputs, selected by `data-accent` on `<html>` or a
container:

`violet` (default, today's values) · `blue` · `teal` · `green` · `orange` ·
`pink` · `slate`

Values are generated by `accentPalette` from a reference colour and then
committed as literal values, so the presets cost no script. A test checks
that each block still matches `accentPalette(reference)`.

### 3. JavaScript API — `src/theme/accent.ts`, exported from `kanto-ds`

```ts
export interface KtAccentPalette {
  base: string;
  hover: string;
  textDark: string;
  textLight: string;
  neutralHue: number;
  neutralChroma: number;
}
export function accentPalette(color: string): KtAccentPalette;
export function setAccent(color: string | null, root?: HTMLElement): void;
export const KT_ACCENTS: readonly { id: string; label: string; color: string }[];
```

- `accentPalette` parses hex (`#rgb`, `#rrggbb`), `rgb()` and `oklch()`;
  throws a `TypeError` on anything else. It keeps the colour's hue and
  chroma and solves, in OKLCH:
  - `base`: the highest lightness (≤ the colour's own) at which white text
    reads at ≥ 4.5:1, chroma reduced only as far as the sRGB gamut needs;
  - `hover`: `base` 0.025 darker;
  - `textDark`: the lowest lightness reaching ≥ 4.5:1 on every dark surface
    text sits on (up to `--color-dark-20` and its own soft tint) at the most
    chroma sRGB allows — the rule the current `-text` tokens follow;
  - `textLight`: the same on the light surfaces (white to `dark-20`).
- `setAccent(color, root)` writes the inputs as inline custom properties on
  `root` (default `document.documentElement`); `setAccent(null, root)`
  removes them, falling back to `data-accent` or the default.
- `KT_ACCENTS` lists the presets with their reference colour, for building a
  chooser.
- Bright hues (yellow, orange) get a darker `base` to keep white text
  readable — the same trade-off as today's violet. Documented.

### 4. Docs site chooser

- In the top bar's actions, left of the theme switch: a small button showing
  the current accent as a dot (`aria-label="Accent colour"`).
- It opens a panel (the existing floating/dropdown pattern) with:
  - the seven presets as a radio group of swatches, arrow keys between
    them, each named ("Blue");
  - "Custom": an `<input type="color">` with the hex beside it.
- The choice is stored in `localStorage` (`kanto-docs-accent`) like the
  theme, and applied before the first render, so no flash.
- Presets apply `data-accent`; a custom colour calls `setAccent`.

### 5. Documentation

- `src/tokens/README.md`: an "Accent colour" section — presets, inputs,
  `setAccent`, the contrast guarantee, the bright-hue trade-off, and that
  red or green accents sit close to danger and success.
- A Guide page in the docs site, "Accent colour", with the chooser's
  presets shown on a few components.
- CHANGELOG, 1.6.0, under Added (a feature, not a component: not bold).

## Testing

- **Default unchanged:** every colour token computes, in both themes, to
  today's value within one sRGB unit (browser test reading
  `getComputedStyle`).
- **Contrast:** `accentPalette` over a sweep of hues × chromas × lightnesses
  and on each preset: white on `base` ≥ 4.5:1, `textDark`/`textLight` ≥ 4.5:1
  on their surfaces, everything in sRGB gamut.
- **Presets match the function.**
- **`setAccent`:** writes and removes the inputs; a subtree accent does not
  leak; switching `data-theme` with a custom accent swaps `-text` without a
  call.
- **Parsing:** accepted forms, `TypeError` otherwise.
- **axe** on a few components under three accents.
- **Visual:** screenshots of the docs site in both themes and Firefox for
  several accents.
- Full `npm run verify` before each commit.

## Out of scope

- A public `kt-accent-picker` component.
- Changing the semantic colours (danger, warning, info, success) or the
  chart palette.
- Server-side generation of a stylesheet from a colour (possible later with
  `accentPalette`, not built now).
